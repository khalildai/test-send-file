一、启动
1. 服务电脑安装 Windows CPython 3.10、3.11、3.12 或 3.13（32 位或 64 位均支持），并在安装时勾选 Add Python to PATH。
2. 双击 `start.bat`。首次启动会自动创建隔离环境，并只从包内 packages 目录离线安装依赖；不需要访问互联网。
3. 如果启动失败，窗口会保持打开，并在同目录生成 `startup.log`。把日志内容发给维护人员即可定位问题。
4. 本机访问 http://127.0.0.1:5000
5. 局域网其他电脑访问启动窗口显示的 LAN URL。
6. Windows 首次询问防火墙权限时，仅允许“专用网络”。

关于 AI：自 V2.0.2 起，DeepSeek API 关联与 AI 相关功能已全部移除，本包不再包含任何 AI 调用、AI 配置页或 AI 数据存储；启动过程也不需要任何 API Key。

二、数据
- 数据库文件：data/maturity.db
- 能力数据、科组、部门、业务、组织关系、修改记录和页面共享配置均由服务端 SQLite 保存。
- 浏览器不再使用 localStorage/sessionStorage/IndexedDB 保存内部数据。
- 用户只通过现有前端页面操作，不需要也不应直接打开数据库。
- 备份时先关闭服务，再复制 data/maturity.db。

三、多人访问
- 使用 Waitress 12 线程服务，目标为局域网内少于 30 人的轻量并发访问。
- 所有写入使用数据库事务和版本校验。若其他用户已先保存，页面会提示刷新，避免静默覆盖。
- 首页“刷新首页”从服务端重新获取最新共享数据。
- 在线修改或 Excel 导入后，点击“刷新首页”会等待当前保存完成，再按最新共享数据统一重算同类型业务组对比、业务线/产品×领域分布和双雷达图。

四、首页新版功能
- 顶部筛选不再显示“细分能力”，新增“能力 Owner”；原始数据台账中仍保留细分能力字段。
- “当前成熟度得分”位于最左侧，其他四张 KPI 保持原顺序右移。
- 同类型业务组对比中的“总体达成”固定为第二列，不随领域筛选数量变化。
- 两张方案 D 雷达图共用当前科组、部门、业务线及其他顶部筛选：第一张显示六个领域当前得分与 3.00 目标，第二张显示各评估维度达成率与 100% 目标。两图不展示细分能力。
- 雷达图采用 20/40/60/80/100 分层背景；蓝色实线圆点为当前实际，金色虚线菱形为目标，并在各轴直接标出实际/目标值。
- 首页已删除“达成状态”和“交付状态”两个圆形图。
- 首页筛选默认收起；同类型对比和评估维度缺口均可独立整体收起或展开。
- Excel 导入完成后会清理已失效的顶部筛选；工作簿中明确存在的科组-能力达成记录会参与同类型对比计算，即使旧组织配置尚未包含该领域关联。

五、日常操作与维护
- 日常启动：双击 start.bat，保持启动窗口开启；本机访问 http://127.0.0.1:5000，局域网同事使用窗口显示的 LAN URL。
- 停止服务：在启动窗口按 Ctrl+C，然后关闭窗口。
- 备份：先停止服务，再复制 data/maturity.db 到安全位置并注明日期。
- 恢复：先停止服务，保留当前数据库备份，再用备份文件替换 data/maturity.db，然后重新启动。
- 启动失败：查看同目录 startup.log，把日志发给维护人员。

六、边界
- V2.0 保留 V1.0 主页面和现有功能，没有新增业务页面。
- SQLite 适用于本次小于 30 人的本地/局域网规模。不要将服务直接暴露到公网。
- 如需更换端口，可编辑启动脚本中的 MATURITY_PORT。

七、离线依赖清单
- Flask 3.1.1
- Waitress 3.0.2
- Werkzeug 3.1.8
- Jinja2 3.1.6
- MarkupSafe 3.0.3（分别提供 CPython 3.10/3.11/3.12/3.13 的 Windows 32 位和 64 位 wheel）
- Click 8.4.2、ItsDangerous 2.2.0、Blinker 1.9.0、Colorama 0.4.6
- 启动脚本设置 PIP_NO_INDEX=1，并使用 --no-index --find-links packages，明确禁止联网安装。
- 如果服务电脑没有 Python，本包不能代替 Python 安装程序；需先离线安装上述支持版本之一。现有 Python 检测结果为 32 时可直接使用此双架构包，无需改装 64 位 Python。
