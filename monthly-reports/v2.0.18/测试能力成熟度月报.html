01报告简介：目标与口径
1.1 目标

年度成熟度目标为 3.0（满分 4.0）。3.0 对应「3 级作为年度重点」已形成可对比的组织能力，而不是个别科组自选范围后的进度完成率。

1.2 计分（V2.0.18）

科组–领域得分 = 2 级达成率 × 2 ＋ 3 级达成率 ＋ 4 级达成率（5 级不计）。科组得分 = 所关联领域得分的算术平均。部门 / 业务线 / 全中心 = 关联科组等权平均。达成判定 0/1。能力项达成率 = 已达成条数 / 总条数。

1.3 数据边界

得分、达成、排名一律用 V2.0.18 正式库。无真实来源的质量结果（缺陷数、reopen）标「临时演示」，不引用未核验的外部数据。历史对比待快照积累，本期不编造上半年曲线。

02管理模式演进（2025→2026）

叙述参考 文字取自成熟度介绍定稿；数字用本期正式库。

2.1 从专项评分到持续经营

2025 痛点：科组自选范围、目标自行选取、结果无法对比、季度跟踪、年底集中验收、偏重进度。2026 转向统一供给与持续运营：统一能力清单、统一目标 3.0、实时跟踪、达成即验收。

2.2 能力设计

能力 Owner 统一设计评估维度并分发至涉域科组。六大领域（软件 / 硬件 / 机械 / EMC / 合规 / 环境可靠性）同域同口径。领域归并：安规 / 合规 / 认证 → 合规；可靠性 / 环境 → 环境可靠性。

2.3 能力阶与运营

2 级打基础，3 级为年度重点，4 级对应数字化 / AI，合集构成年度目标。5 级不计入本期得分。运营节奏：实时跟踪、达成即验收、落地辅导。

2.4 价值兑现

可诊断（识别差距）、可对比（科组 / 部门 / 业务横向）、可引导（分层改进）。三类读者：科组与部门负责人看短板与计划；Owner 看领域供给；测试管理者看中心目标风险。

用本期真实数对照这套模式：全中心 1.75，距 3.0 仍差 1.25 分，说明「统一目标」已经立住，但多数组织仍停在 2 级基底，尚未把 3 级年度重点做成可验收结果。

4.4 改进建议（本章必须出现）
  1. 目标锚点：一切对比以 3.0 为准，不以「比上月多达成几条」替代。

06后续改进计划
6.1 闭环原则

未达成项 → 计划月份 → 验收 → 得分上升。没有计划月份的项不进入 12 月预测。本报告不列出操作日志。

6.2 90 天动作
  1. 中心（管理者）：盯 1.75→2.2 的结构变化，而不是 1984 条的周增量。每月只看：后 5% 科组、最低领域、未标计划月份的未达成项。
  2. 部门负责人：用本部门均值当尺子。低于部门均值的科组要有 9–12 月计划；高于均值的组转入 3 级验收，不重复 2 级运动。
  3. 能力 Owner：对最低领域做一次供给检查——是清单过重、还是辅导未落地。同域目标仍是 3.0，不给短板领域另开一套分。
  4. 后 5% 科组：只承诺可在 90 天验收的 2 级项。禁止用「规划中的 4 级」掩盖 2 级空洞。
